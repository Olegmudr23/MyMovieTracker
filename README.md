# Кинокруг

Трекер фильмов и сериалов с личной коллекцией, оценками, прогрессом сериалов, публичными подборками, рекомендациями другим аккаунтам и обсуждениями. Русский адаптивный интерфейс. Новости — тестовые редакционные публикации.

## Локальный запуск

Нужен Node.js 24+. Сторонние npm-пакеты не нужны.

```powershell
Copy-Item .env.example .env
npm start
```

Откройте http://localhost:3000. Для разработки — `npm run dev`. Проверки — `npm test`.

Зарегистрируйте два аккаунта, чтобы проверить рекомендации: в карточке фильма выберите «Рекомендовать другу» и укажите email второго аккаунта. Просмотренные фильмы и оценки доступны по ссылке из «Моя коллекция → Поделиться просмотренным». Имя пользователя тоже публично по этой ссылке. В планах и прогресс просмотра не публикуются. Для сериалов пока ведётся общий номер последней просмотренной серии, без разбивки по сезонам.

## Каталог

Интеграция с [Kinopoisk API Unofficial](https://kinopoiskapiunofficial.tech/) — это сторонний неофициальный API, не официальный API Яндекса. На сайте провайдера заявлен лимит для новых пользователей 500 запросов в сутки; проверьте текущие условия перед запуском. Зарегистрируйтесь у провайдера и скопируйте собственный ключ в `.env`:

```dotenv
KINOPOISK_API_KEY=ваш_ключ
```

[Документация API](https://kinopoiskapiunofficial.tech/documentation/api/). Сервер использует `GET /api/v2.2/films` с keyword и `GET /api/v2.2/films/{id}`, передавая ключ в X-API-KEY. Ответы кешируются в SQLite: поиск и каталог на 6 часов, полные карточки на 7 суток. Кэш общий для пользователей и сохраняется после перезапуска. Одновременные одинаковые запросы объединяются в один запрос к провайдеру. При недоступности API сохранённый ответ может использоваться ещё 7 суток после истечения срока; повторные неудачные обращения приостанавливаются на минуту, при HTTP 429 учитывается Retry-After. Ошибки и некорректные ответы не сохраняются. Хранится до 3000 ответов; просроченные записи удаляются при успешных загрузках. Поисковые фразы нормализуются по регистру и пробелам. Ключ никогда не отправляется браузеру. Без ключа отображается демонстрационный каталог. При сбое API используется допустимый старый кэш; если его нет, показывается ошибка. Демо не подменяет ответы подключённого API. Живой поиск и загрузка карточки проверены с ключом владельца.

Демо-постеры загружаются с CDN TMDB; редакционный баннер и демо-карточки не означают подключения к API TMDB. Недоступные картинки заменяются цветовым фоном. Для коммерческого запуска проверьте условия использования изображений и данных.

## Данные и вход

- SQLite: `data/kinocircle.sqlite`, WAL. Все изменения сохраняются на сервере.
- Пароли: асинхронный scrypt, индивидуальная случайная соль 16 байт, результат 64 байта. Исходные пароли не сохраняются.
- Email не сохраняется в открытом виде: используется HMAC-SHA256 нормализованного email. Это позволяет выполнять вход и искать адресата рекомендации без хранения исходного адреса. Отправка писем, подтверждение email и восстановление пароля не реализованы.
- Секрет HMAC автоматически создаётся в `data/identity.key`. Можно задать постоянный `IDENTITY_SECRET` через окружение. Не меняйте его после регистрации пользователей: прежние email перестанут находиться.
- Сессии: случайный токен 32 байта, в БД только SHA-256 токена, срок 7 дней. Cookie HttpOnly, SameSite=Lax; Secure при `COOKIE_SECURE=1`.
- Проверка Origin для изменяющих запросов, CSP, параметризованные SQL-запросы, экранирование пользовательского текста, ограничение размера тела и частоты попыток входа по адресу соединения.
- За обратным прокси лимит входа может быть общим для пользователей: перед публичным запуском настройте дополнительное ограничение на прокси. Приложение намеренно не доверяет произвольному X-Forwarded-For.

## Размещение на Timeweb

Для текущей SQLite-версии используйте **VPS/VDS Timeweb Cloud с Docker Compose и постоянным диском**. Это не конфигурация для обычного PHP-хостинга.

В [документации Timeweb App Platform](https://timeweb.cloud/docs/apps/deploying-with-docker-compose) перечислены запрещённые директивы, включая `volumes`. Поэтому данный `compose.yaml` предназначен для VPS, а не для App Platform. Запуск SQLite без постоянного тома в App Platform может потерять данные при пересоздании контейнера. Для App Platform сначала требуется переход на внешнюю БД.

1. Создайте VPS, установите Docker Engine и Compose, скопируйте этот проект на сервер.
2. Скопируйте `.env.example` в `.env`, заполните ключ каталога, установите `COOKIE_SECURE=1`.
3. Запустите `docker compose up -d --build`. Именованный том `movie_data` хранит базу и секрет между пересозданиями контейнера.
4. Настройте домен и HTTPS через Nginx/Caddy перед приложением. Пример Nginx после получения сертификата — в `deploy/nginx.conf`. Для TLS укажите свои реальные пути сертификатов. Порт приложения привязан только к loopback VPS.
5. Проверка состояния: `GET /api/health`. Просмотр логов: `docker compose logs --tail=100 app`.
6. Обновление: скопируйте новую версию, выполните `docker compose up -d --build`. Не удаляйте том `movie_data`.

Для пробного Docker-запуска без HTTPS установите `COOKIE_SECURE=0`; перед доступом по публичному домену включите HTTPS и Secure cookie.

### Резервная копия

Остановите приложение `docker compose stop app`, затем скопируйте **всё содержимое** тома `movie_data` средствами резервирования VPS/Docker и снова запустите `docker compose start app`. Сохраните базу вместе с `identity.key` (или отдельно сохранённым IDENTITY_SECRET). При восстановлении они должны соответствовать друг другу. Копирование одного SQLite-файла во время работы небезопасно из-за WAL.

## Границы первой версии

Нет SMTP, восстановления пароля, списка дружбы с запросами, модерации, загрузки собственных постеров и административной панели. Рекомендации отправляются между зарегистрированными пользователями по email. Новости редактируются в `public/app.js`, это тестовый раздел без автоматического сбора. Публичная подборка содержит просмотренные фильмы пользователя; создание нескольких именованных подборок пока не реализовано. Для больших нагрузок потребуется внешняя БД и распределённый лимитер. Публикация на Timeweb в этой сессии не выполнялась.
